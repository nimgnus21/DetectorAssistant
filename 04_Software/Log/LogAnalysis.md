# Log Analysis

> iDetector Software Module - Log Analysis

---

# 1. Purpose

The **Log Analysis** function is used to analyze software operation records generated by iDetector.

By reviewing log information, engineers can understand software execution status, detector communication status, SDK responses, and operation results, assisting in troubleshooting and technical support.

This document describes how to interpret and analyze log information within the iDetector software.

---

# 2. Scope

This document applies to log records generated during:

- Software startup
- Detector connection
- Detector configuration
- Image acquisition
- Calibration
- Firmware upgrade
- SDK communication
- Software exceptions

---

# 3. Log Components

A typical log record may contain the following information.

| Item | Description |
|------|-------------|
| Time | Time when the event occurred |
| Module | Software module generating the log |
| Level | Information level of the log |
| Message | Description of the event |
| Result | Execution result, if applicable |

The displayed fields depend on the software version.

---

# 4. Log Levels

The Log module may contain different categories of messages.

## Information (Info)

Records normal software operations.

Typical examples:

- Software started
- Detector connected
- Image acquired successfully
- Calibration completed

---

## Warning (Warning)

Indicates that the operation completed, but attention may be required.

Typical situations include:

- Communication delay
- Detector response timeout warning
- Parameter mismatch warning

Warnings do not always indicate a failure but should be reviewed.

---

## Error (Error)

Indicates that an operation failed or an unexpected condition occurred.

Examples include:

- Detector connection failure
- SDK initialization failure
- Image acquisition failure
- Calibration failure
- Firmware upgrade failure

Error logs should be retained for further analysis.

---

# 5. Log Analysis Principles

When reviewing logs, engineers should analyze events in chronological order.

Recommended approach:

1. Identify the operation being performed.
2. Locate the corresponding log entries.
3. Review Warning and Error messages.
4. Determine whether the operation completed successfully.
5. Correlate software logs with detector status and observed symptoms.

---

# 6. Engineering Recommendations

When analyzing logs:

- Review the complete sequence of events.
- Do not analyze a single isolated message without context.
- Preserve original log records before repeating tests.
- Compare log timestamps with actual operation time.

---

# 7. Notes

- Log contents vary with software version.
- Some messages are intended for engineering diagnosis.
- Debug information may only be available in engineering or development versions.
- Do not modify exported log files before submitting them for analysis.
